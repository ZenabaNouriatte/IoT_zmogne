Problemes rencontres : 

- Ajout de l'option -y pour les provision vagrant 

- Installation k3s agent bloque : il faut un token 

Comment recup ce token ? commande ```cat /vagrant/node-token``` fichier cree automatiquement par le server 

Si je met le token en dur : meme soucis 

SW demarrait en meme temps que S : pas possible il faut que S demarre puis SW pour la recup du token ( constate car impossible d'ouvrir S quqnd SW est en cours de config) 

Forcer a verifier si zmogneS st bien lance avant l'installation d'agent sur zmogne SW car besoin de communiquer avec zmogneS 

OK mais creation d'agent k3s mouline ...

**Solution :** augmentation cpu et memory 


- Tout se lance mais apres verification si je me connecte en ssh a S et que je fais la commande  ```sudo kubectl get nodes -o wide``` , je vois les deux machines mais ip pas ok (internal ip = 10.0.2.15 et non l'ip attribuee)

**Solution :** ajout -bind-address, --advertise-address, --node-ip et --flannel-iface=eth1 à l'installation K3s


2. Commandes utiles
Commande pour eteindre et recommencer

```VBoxManage controlvm "zmogneS" poweroff   
VBoxManage controlvm "zmogneSW" poweroff   

VBoxManage unregistervm "zmogneS" --delete
VBoxManage unregistervm "zmogneSW" --delete

vagrant destroy -f                        
vagrant up```

Dans les machines verifier si tout est ok 
Sur S : 
```sudo kubctl get nodes -o wides``` voir les deux nodes ready et les bonnes ip

On peut aussi faire ```ip a show eth1``` pour voir dans inet l'adresse ip
Sur SW : ```systemctl status k3s-agent``` voir voir active (running)
