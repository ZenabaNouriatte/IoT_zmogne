## Objectif

Mettre en place une infrastructure GitOps :
- Un cluster Kubernetes leger via K3d (K3s dans Docker)
- Argo CD qui surveille un repo GitHub et deploie automatiquement une app
- Deux namespaces : argocd et dev

## Architecture

```bash
Machine de travail (Ubuntu 24.04)
│
├── Docker
│     └── K3d (cluster Kubernetes dans des conteneurs Docker)
│               ├── namespace argocd → Argo CD tourne ici
│               └── namespace dev    → app deployee automatiquement
│
├── kubectl → parle au cluster via ~/.kube/config
└── GitHub (repo public IoT)
└── Argo CD surveille p3/confs/
└── deploie automatiquement dans namespace dev


Ma machine 
    │
    ├── K3d 
    │    └── a créé des conteneurs Docker :
    │               ├── k3d-iotcluster-server-0   (le cerveau K3s)
    │               ├── k3d-iotcluster-tools       (outils K3d)
    │               └── k3d-iotcluster-serverlb    (load balancer)
    │
    └── kubectl (sur ta machine)
            └── doit parler au cluster K3d
```

## Differences K3s vs K3d
- K3s : Kubernetes leger qui tourne dans des VMs (utilise Vagrant)
- K3d : K3s qui tourne dans des conteneurs Docker, plus leger et plus rapide
- K3d ne necessite pas Vagrant ni VirtualBox, juste Docker

## Fichiers crees

### scripts/install.sh
Installe tous les outils necessaires sur la machine :
- Docker
- K3d
- kubectl
- Argo CD CLI

### scripts/launch.sh
Lance l'infrastructure :
- Cree le cluster K3d
- Configure kubectl
- Cree les namespaces argocd et dev
- Installe Argo CD

### Problemes rencontres et solutions
1. kubectl connection refused localhost:8080
**Probleme** : kubectl ne savait pas ou etait le cluster
**Cause** : le fichier kubeconfig n'etait pas au bon endroit
**Solution** :
```bash
mkdir -p ~/.kube
```
**Explication** : kubectl cherche sa config dans ~/.kube/config par defaut

2.Docker repo Debian au lieu de Ubuntu

**Probleme** : le script utilisait le repo Docker pour Debian sur une machine Ubuntu

**Erreur** : 404 Not Found sur download.docker.com/linux/debian

**Solution** : remplacer debian par ubuntu et VERSION_CODENAME par UBUNTU_CODENAME

3. Cannot connect to Docker daemon

**Probleme** : make launch utilisait sudo, donc cherchait le socket Docker de root

**Erreur** : Cannot connect to the Docker daemon at unix:///var/run/docker.sock

**Solution en deux etapes** :
Ajouter l'utilisateur au groupe docker
```bash
sudo usermod -aG docker $USER
``` 
+ supp sudo du makefile

### Commandes utiles

```bash
# Verifier que le cluster tourne
kubectl get nodes

# Verifier les namespaces
kubectl get ns

# Verifier les pods Argo CD
kubectl get pods -n argocd

# Eteindre le cluster sans le supprimer
k3d cluster stop iotcluster

# Rallumer le cluster
k3d cluster start iotcluster

# Supprimer completement le cluster
k3d cluster delete iotcluster

# Verifier la RAM disponible
free -h
```
